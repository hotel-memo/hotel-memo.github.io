# 宿泊メモ作成スキル

宿泊メモを対話的に作成する。ユーザーから情報を聞き取り、`content/memos/{chain}/{hotel}/{room}.md` を生成する。必要に応じてホテル index (`index.md`) も同時に作る。

## 手順

### 1. 情報の聞き取り

以下をユーザーに確認する。既に会話中で伝えられている項目はスキップする。

**必須:**
- ホテル名（日本語）
- 部屋タイプ名（日本語、例: エグゼクティブルームツイン）
- パソコン作業の快適さ rating（1〜5）
- 宿泊した部屋番号
- 宿泊日（範囲 or 単日）

**任意（あれば聞く）:**
- チェーン名（既存: hilton, hyatt, ihg, jr-east-mets, daiwa-roynet, tokyu。新規も可）
- ホテル公式サイト URL
- 部屋の画像ファイル（ローカルパス）
- cover / og_cover にする画像
- パソコン作業の快適さに関するコメント
- 部屋情報（面積、ベッドタイプ、喫煙/禁煙、特典など）
- 部屋の設備・特徴に関するメモ

一度に全部聞かず、まずホテル名・部屋タイプ・rating・宿泊日を聞き、残りは段階的に確認する。

### 2. slug の決定

AGENTS.md の slug 規約に従う:
- chain: 英字 kebab-case（例: `hilton`）
- hotel: 英字短名（例: `hilton-fukuoka-seahawk`）
- room: 部屋タイプの英字短名（例: `exec-suite-king`）

既存の `content/memos/` 配下のディレクトリ名を確認し、命名の一貫性を保つ。新規の chain / hotel の場合はユーザーに slug 案を提示して確認する。

### 3. ホテル index の確認・作成

`content/memos/{chain}/{hotel}/index.md` が存在しない場合、以下の形式で作成する:

```markdown
---
title: {ホテル名（日本語）}
chain: {チェーン名（日本語）}
official: {公式サイトURL}
---
```

`official` が不明なら省略する。既存の index.md がある場合は何もしない。

### 4. 画像の配置

ユーザーが画像ファイルのパスを提供した場合:

1. `content/images/YYYY/MM/` ディレクトリに配置する（YYYY/MM は宿泊月）
2. ファイル名はそのまま使う（リネーム不要）
3. Markdown 本文では `/images/YYYY/MM/filename.jpg` の絶対パスで参照する
4. cover / og_cover をユーザーに確認し、frontmatter に設定する

### 5. メモファイルの生成

以下のフォーマットで `content/memos/{chain}/{hotel}/{room}.md` を生成する:

```markdown
---
title: {ホテル名} {部屋タイプ名}
rating: {1-5}
stayed_at: {最新の宿泊日, YYYY-MM-DD}
cover: {画像パス、あれば}
og_cover: {画像パス、あれば}
---

## パソコン作業の快適さ

{快適さに関するコメント、箇条書き}

## 部屋情報（公式サイトより）

- 面積: {面積}
- ベッド: {ベッドタイプ}
- 喫煙/禁煙: {禁煙 or 喫煙}
{その他の情報}
- 参照元: {公式サイトURL} （取得日: {YYYY-MM-DD}）

## {部屋番号}号室

{宿泊日: YYYY/M/D-D or YYYY/M/D-YYYY/M/D or YYYY/M/D}

{部屋のメモ、箇条書き}

{画像: ![](/images/YYYY/MM/filename.jpg) を1行ずつ}
```

**注意点:**
- `## パソコン作業の快適さ` セクションは必須（内容が空でも見出しは置く）
- `## 部屋情報（公式サイトより）` は情報があるときだけ
- 宿泊日の書式は rehype-stay-date プラグインが解釈する正規フォーマットのみ:
  - 同月範囲: `2025/11/10-17`
  - 月またぎ範囲: `2025/12/30-2026/1/3`
  - 単日: `2025/11/10`
- `stayed_at` frontmatter は最新の宿泊日（YYYY-MM-DD 形式）
- title は「{ホテル名} {部屋タイプ名}」（スペース区切り）
- ユーザーが提供した情報のみ書く。不明な項目は省略し、推測で埋めない

### 6. 確認

生成したファイルの内容をユーザーに見せて確認を取る。修正があれば対応する。

## このスキルがやらないこと

- ブランチ作成・コミット・PR 作成（ユーザーが別途指示する）
- 地域カタログ (`content/regions/`) の更新
- 既存メモの編集
